{# Multilingual phase 2: the one component for a text that may be shown in a machine translation. per paragraph (posts), each through linkify on_request posts and facts: translated on request; false for issues and proposals, which are translated right away (app/content_jobs.py) request_url the forum translate route (POST) for a logged-in reader; none: no translate button (visitors) auto posts: the reader's "always translate" preference id an id for the original's element (the edit script uses it) A {% call %} block adds content after the text inside the element (a badge). Both texts are in the page, no request. A post without "always translate" starts on the original ("Original in · Show translation"); - no translation yet: issues and proposals show the original with "Translation pending" (never an AI call on a page load); a post shows "Original in · Translate", which fetches the translation (static script in base.html) and then behaves as above. #} {% macro _text(el, cls, text_lang, text, rich, paras, extra, id=none, role=none, hidden=false) -%} <{{ el }}{% if cls %} class="{{ cls }}"{% endif %}{% if id %} id="{{ id }}"{% endif %} lang="{{ text_lang }}"{% if role %} data-mt-{{ role }}{% endif %}{% if hidden %} hidden{% endif %}> {%- if paras %}{% for para in (text or '').split('\n\n') %}
